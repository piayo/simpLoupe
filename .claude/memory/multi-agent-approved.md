simpLoupe では**ワークフロー（マルチエージェント）を使ってよい**。毎回確認を取らなくてよい。

**Why:** 2026-08-11 のセッションで「マルチエージェントで、トークン気にせずに、ゼロベースで考えて」と
明示的に指示された。姉妹プロジェクト g-calize でも同じ許可が出ている。

**How to apply:**
- 独立した作業に分割できるとき（領域ごとの実装、調査の並列化）は積極的に使う
- **書き込みパスを完全に分離する。** `package.json` / `package-lock.json` は
  競合するので全エージェントに編集禁止とし、統合は自分でまとめて行う
- simpLoupe は `src/ts/` が 1,000 行未満なので、**調査系のエージェントには
  「対象ファイルを全部読んでから書くこと」を明示できる**。g-calize（約4600行）のように
  部分読みで済ませる必要はない。推測で書かせないこと
- 実装エージェントの自己申告は信用せず、**敵対的な検証エージェント**を通す。
  「自分でコマンドを実行して裏を取ること」「ファイルを編集しないこと」を指示すると効く
  — 実際に設計エージェント5体の主張のうち5件が実測で覆った
- 検証エージェントは `git status` を見るので、**自分の未コミットの変更が誤検知される**点に
  注意して結果を読む
- **起動したエージェントの数を必ず数える。** `parallel()` に3件渡して `started` が2件しか
  journal に出ず、1体が黙って起動していなかったことがある。
  `subagents/workflows/<runId>/journal.jsonl` の `started` を数え、
  足りなければ自分で引き取る
- 進捗は必ず可視化する → [[progress-reporting]]

リポジトリ側の規約（コードスタイル、生成物の扱い、保存済み設定キーの扱い、i18n の2系統）は
`CLAUDE.md` に書いてあるので、エージェントのプロンプトにも「まず CLAUDE.md を読むこと」を入れる。
